# 로컬 테스트 가이드

## 1. Mock 모드로 UI만 확인하기 (백엔드 불필요)

`frontend/js/api.js`의 `MOCK_MODE`는 기본값이 `true`입니다. 아래 명령으로 정적 서버를 띄우고 브라우저에서 열어보면 가짜 데이터(`IPR0001`~`IPR0004`)로 전체 화면 흐름을 확인할 수 있습니다.

```bash
cd frontend
npx --yes serve -l 5173 .
```

`http://localhost:5173` 접속 후 IPR바코드 입력창에 `IPR0001`을 입력하고 Enter를 누르면 조회 결과가 나타납니다(카메라 없이도 PDA 흉내를 낼 수 있습니다).

## 2. 테스트 스프레드시트 + Apps Script 연동하기

1. 새 구글 스프레드시트를 만들고, 탭 이름을 정확히 `회송리스트`로 변경합니다. 1행에 실제 시트와 동일한 헤더(DATE, FC, 오류 유형, ..., 매칭행(h))를 넣고, 몇 개의 샘플 행을 채웁니다(F열에 테스트용 IPR바코드 입력).
2. `log`라는 이름의 빈 탭을 하나 더 만듭니다(앱이 첫 처리 시 헤더를 자동으로 채웁니다).
3. 메뉴에서 확장 프로그램 → Apps Script를 엽니다.
4. 기본 생성된 `Code.gs`의 내용을 지우고, 이 저장소의 `appsscript/` 폴더에 있는 파일들을 순서 상관없이 각각 새 스크립트 파일로 만들어 내용을 그대로 붙여넣습니다: `Logic.js`, `Sheet.gs`, `Drive.gs`, `Handlers.gs`, `Code.gs`. (파일명 끝의 `.gs`/`.js`는 크게 중요하지 않으며, Apps Script 편집기의 "파일 추가 → 스크립트"로 만들면 자동으로 `.gs`가 붙습니다.)
5. 우측 상단 "배포 → 새 배포"를 클릭 → 유형: 웹 앱 → 실행 계정: 나, 액세스 권한: 링크가 있는 모든 사용자로 설정 후 배포합니다.
6. 발급된 웹 앱 URL을 복사합니다.
7. `frontend/js/api.js`에서 `MOCK_MODE`를 `false`로, `API_BASE_URL`을 방금 복사한 URL로 바꿉니다.
8. 다시 `cd frontend && npx --yes serve -l 5173 .`로 서버를 띄우고, 테스트 시트에 넣어둔 IPR바코드로 스캔 → 조회 → 처리까지 실제 시트가 업데이트되는지 확인합니다.

## 3. 오프라인 동작 확인하기

1. Mock 모드 또는 실제 배포 모드로 앱을 정상 로그인한다(로그인 시 자동으로 `syncDown`이 호출되어 미처리 건이 기기에 저장된다).
2. 브라우저 개발자도구의 네트워크 탭에서 "오프라인" 체크박스를 켜거나, 실제로 기기의 Wi-Fi/데이터를 끈다.
3. 스캔 대기 화면에서 방금 다운로드된(=아직 처리 안 된) IPR바코드를 조회하면, 네트워크 요청이 실패하고 로컬 스냅샷에서 찾아 평소와 동일한 카드가 표시된다.
4. 스냅샷에 없는(예: 원래 미등록이거나 이미 처리된) IPR바코드를 조회하면 "재확인 필요(오프라인 상태)"가 표시된다.
5. 폐기/회송 처리를 완료하면 "(오프라인 처리 — 동기화 대기 중)" 문구와 함께 완료되고, 화면 상단 "동기화 대기: N건" 숫자가 올라간다.
6. 네트워크를 다시 켜고 [지금 동기화] 버튼을 누르면 큐에 쌓인 건이 실제 시트에 반영되고, 결과 요약(반영/중복/미확인 건수)이 표시된다.
7. 두 기기(또는 브라우저 탭 두 개)로 같은 IPR바코드를 각각 오프라인 처리한 뒤 순서대로 동기화해보면, 먼저 동기화된 값이 시트에 남고 나중 것은 AC열("중복/재신고 점검")에 "중복스캔"이 추가되는지 확인할 수 있다.

## 4. 오입력 방지 기능 확인하기 (v3.1)

1. 아무 IPR바코드나 조회한 뒤 [폐기 처리] 또는 [회송 처리]로 들어가서 [뒤로가기]를 눌러보면, 재스캔 없이 방금 조회했던 카드로 바로 돌아오는지 확인한다.
2. 조회 카드 맨 위에 IPR바코드가 뜨는지, 상품바코드 뒤 4자리가 강조 표시되는지 확인한다.
3. [회송 처리] → [업체직접회수]에서 [회송존 이동]/[회수 완료] 각각을 눌러보고, 확인창이 뜨는지, 취소를 누르면 아무 처리도 안 되는지, 확인을 누르면 실제로 처리되는지 확인한다. 실제 시트 연동 중이라면 [회송존 이동]은 U열/X열만 채워지고 S/T열은 비어있는 채로 남는지, [회수 완료]는 기존처럼 S/T열이 채워지는지 확인한다.

## 5. Node 단위 테스트 실행

```bash
cd frontend && npm test
cd ../appsscript && npm test
```

Node 20 이상이 필요합니다(`node --test`가 `*.test.js` 파일을 자동으로 찾습니다).
